# TaskbarLyrics Browser Companion

Chrome / Edge Manifest V3 扩展，当前版本 `0.2.7`。与桌面程序同仓维护，独立打包、独立发布；本地协议信封版本为 `1`，可协商媒体详情版本 `1`。生产代码不依赖 npm 包、远程脚本或网页框架。

继续开发先读[采集范围与开发交接](../docs/浏览器扩展开发交接.md)，其中区分已确认目标、当前实现、实机证据及待补齐事项。该文档可作为换环境继续开发的入口。

## 本机安装

1. 使用包含本次功能的桌面程序，在「播放器 → 浏览器」中点击对应浏览器的「配置浏览器扩展」。程序注册当前用户的 Native Messaging 连接并打开随程序提供的 `BrowserExtension` 目录。
2. 当前尚未上架。在 `edge://extensions` 或 `chrome://extensions` 开启开发者模式，选择「加载解压缩的扩展」，选择打开的目录。无需管理员权限。
3. 更新扩展后刷新已经打开的播放器页面，使新采集脚本能在页面启动时观察媒体与时间轴。
4. 在扩展弹窗点击「添加并授权当前网站」，或先在桌面程序添加网站，再到扩展弹窗授权。授权由浏览器确认。
5. 开启桌面程序浏览器卡片的识别开关。添加网站会开启「按网站识别」，但不会代替用户开启浏览器识别总开关。

浏览器卡片默认关闭；尚未启用网站识别时，保持原 SMTC 监听。健康连接且网站识别开启后，仅启用的列表网站参与；空列表和未授权网站不会转回通用监听。扩展连接断开保留最多 2 秒宽限，心跳超过 6 秒视为失效，随后恢复通用监听，可能识别列表之外的网站。重新连接并确认配置后恢复网站规则。

规则按协议、域名、端口匹配，不自动包含子域名或其它端口。继承该网站真实来源的 about:blank／srcdoc／blob 内嵌页面也可参与；来源以浏览器提供的 MessageSender.origin 为准，拒绝不透明来源，不使用顶层标签地址替代 iframe 来源。浏览器的授权范围本身可能覆盖该域名的所有端口，扩展仍会按精确 origin 再过滤。

桌面程序移动到新目录后，重新点击「配置浏览器扩展」，更新本机宿主路径。移除扩展在浏览器扩展管理页完成；扩展目录需要保留在固定位置。

## 网站与控制范围

- 获取获准页面标准 `audio` / `video` 元素（包括播放后仍未挂入 DOM 的媒体）与 Media Session 信息。标准歌曲元数据优先，无法关联时间轴时仍保留歌曲信息和未知进度。元素连续两次匹配其时长与进度、间隔至少 750ms 后才关联；仅有元数据且声明状态为 none 时，可关联同文档唯一正在播放、未静音的原生媒体，暂停预加载不作为竞争播放。暂停／静音时可保留已有媒体关联，同时多路未静音媒体播放时撤销时间轴关联。静音背景视频和跨文档不作为首次关联依据。关联后直接跟踪网页拖动。
- 区分播放证据与时间轴身份：多个未静音媒体同时播放时，允许保留该文档正在播放的状态，但位置保持未知，不任选一个进度；多个媒体均暂停且没有既有关联时，也不任选暂停对象。0.2.5 不再将回退限制为有限时长的 AUDIO，支持 VIDEO 与开放时长；开放总时长继续为空，不伪造结束点。诊断分别记录原始音视频标签数、开放时长数、实际播放与未静音播放数及所选标签。
- 借鉴 WebNowPlaying 的通用模块：无标准歌曲元数据时，依次使用 `og:title`、`meta[name=title]`、页面标题，清理播放符号，仅从明确的 `, by`／`by:` 分隔提取歌手；不把网站名或普通连字符当作歌手。零／未知时长的未就绪元素不成为候选；直播保留未知总时长。普通页面信息保持备用标题来源标记。
- 0.2.3 在 Audio 创建、document.createElement／createElementNS 创建媒体和原生 load 时登记弱引用，补充只观察 play 的盲点；保留原生实例、原型、返回值和异常语义，不强持有旧媒体。页面诊断增加观察到的媒体数、有效媒体数、声明状态和动作数，不记录歌曲正文或资源地址。
- 正在播放的候选优先，然后按网站顺序；同站同状态时标准媒体标题优先于页面标题备用信息，同等质量保留当前候选。浏览器整体继续使用桌面播放器排序与 Browser 的歌词来源及偏移配置。
- 控制命令绑定浏览器配置文件、文档和媒体元素。旧文档关闭后不把命令转发到其他标签页。上一首、下一首需要网页注册 Media Session 回调；已经打开页面可刷新，以在页面初始化阶段捕获回调。
- 封面依次使用标准 Media Session artwork、已选视频自身的 poster、单一有效媒体文档的 `og:image`；不把背景视频封面补给无法关联的歌曲。仅接受 HTTP(S) 候选，由桌面按尺寸选择并异步读取，限制类型、字节数与重定向，并隔离旧曲目下载结果。公开图片或获准网站的同源图片可读取；没有浏览器 Cookie 转发，需登录的图片、blob／data 图片和网站私有封面接口尚不支持。无封面继续使用浏览器图标。
- 0.2.6 增加通用 Web Audio 播放证据：当标准 Media Session 为 none／unknown 且没有可关联的播放媒体时，运行中的 `AudioContext`／`webkitAudioContext` 只用于维持“正在播放”状态，不提供位置或时长。夹具中该路径可保留只有静音短视频的歌曲信息；但 MCP 复核 Spotify 主页面仍未捕获到其 Web Audio 上下文，页面继续报 `media-session Playing=false`，因此不能宣称 Spotify 已由本版修复。若音频上下文位于其他 frame／realm，需要另行评估通用跨文档关联或网站专用模块。更新扩展或重载扩展后仍需刷新媒体页面，使旧 relay 上下文停止且新 MAIN 脚本生效。
- 0.2.7 借鉴 Web Scrobbler 的标签页 audible 思路：worker 读取浏览器提供的发送标签页是否发声，只在页面声明 `unknown` 时把它作为“正在播放”证据；显式 paused／ended 不会被覆盖，位置和时长仍保持未知。Web 6 个文件 60 项、打包回归 13 个运行文件通过；包为 `tmp/browser-extension/TaskbarLyrics-Browser-0.2.7.zip`。MCP 重载 0.2.7 后仍记录 `Playing=False`，需确认 Spotify 播放设备是当前网页且标签页未被静音；若标签页本身不发声，通用层没有可靠播放证据。
- 媒体详情协商后传输数据来源、曲目版本、显式未知时间轴、速率、采样年龄、时间锚点年龄、可跳转区间和逐项控制能力。未知进度显示 --:--，歌词区显示歌曲信息，不用零秒驱动歌词；控制面板分别禁用不可用按钮。命令区分拒绝、效果已观察与尚未确认，回执必须对应待处理请求；不将处理器返回视为实际效果证明。
- 未提供标准媒体元素或 Media Session 的纯 Web Audio、自定义封闭播放器、未授权的跨域 iframe，以及缺少准确元数据的网站暂不保证支持。网页全局 Media Session 信息与多个媒体元素也可能不完全对应。
- SMTC 去重和断连降级以 Chrome / Edge 类别为单位。Windows SMTC 不能可靠映射到浏览器配置文件；多配置文件混用、第三方 Chromium 浏览器尚未完成兼容验证。
- 0.1.2 已在 Edge 网页 Spotify 实测，用户确认歌曲与歌词进度正常。真实飞牛音乐、Bilibili、浏览器重启/休眠及商店包安装尚未逐项验收，不以自动化模拟替代这些实机证据。

0.1.2 曾在隔离模拟中复现背景视频与歌曲时间轴混用，通用夹具已回归该问题和关联元素前后跳转。0.2.1 在真实 Spotify 刷新后收到了详情字段，但仍出现元数据与唯一音频未关联、歌手及封面丢失；0.2.2 补齐该路径，并让失效扩展上下文停止上报。新版仍需实机复验。纯 Media Session 且网页不及时更新位置、没有可可靠关联元素时，不能保证立即检测网页跳转。网易云的通用采集实际能力尚待确认，本版没有网站专用选择器或 SMTC 自动关联补充。先完成通用能力矩阵，再评估网站适配。详见开发交接文档。

0.2.2 实机已确认 Spotify 可以采集标准歌曲及封面候选，但页面本地播放时仍缺少状态与时间轴，暂停恢复、关闭迷你播放器和受控刷新未使其恢复。0.2.3 新增媒体创建／加载观察的回归覆盖，但该路径是否解决这次真实页面问题仍需更新后验证；不能将候选封面存在等同于桌面已显示封面。

重新安装 0.2.3 后已确认新诊断生效，Spotify 可发现 2～3 个媒体、多个有效对象及 5 个注册动作，但仍未关联时间轴。0.2.4 调整预加载／多音频筛选并保留文档级播放证据，真实效果待新包复验。用户反馈网易云网页已能采集歌曲信息，歌词、时间轴和封面尚未完整确认。

0.2.4 的 Spotify 实际分类显示多数样本 AudioCount=0、同时有多个有效媒体，偶见有限时长音频处于静音／零音量播放。旧 AudioCount 仅统计有限时长 AUDIO，不能据此断言所有对象都是 VIDEO。0.2.5 修正类型／时长筛选并补充分类型诊断，真实页面仍待更新验证；不保证仅凭通用播放状态就能证明任意复杂页面的歌曲与媒体一一对应。

## 维护与独立发布

```powershell
node scripts/sync-browser-extension-locales.mjs
powershell -ExecutionPolicy Bypass -File scripts/package-browser-extension.ps1
```

从仓库根目录运行，ZIP 默认写入忽略目录 `tmp/browser-extension/`。打包器显式使用 `/` 作为 ZIP 目录分隔符，避免 Windows 压缩工具生成的反斜杠导致浏览器将语言目录视作非法文件名。打包回归可单独运行 `powershell -ExecutionPolicy Bypass -File scripts/package-browser-extension.tests.ps1`，校验原始 ZIP 头与资源内容。扩展版本只维护在 `manifest.json`；桌面程序不要求同步版本，但协议版本必须兼容。UI 文案的唯一维护点仍是 `TaskbarLyrics.App/text.yaml` 中的 `EXT_` 键，`_locales` 为生成的可直接安装资源，修改文案后运行同步脚本。

`distribution.json` 中 `chrome` / `edge` 为各自商店的 32 位扩展 ID，目前均为空。商店条目创建后填写真实 ID 并发布桌面更新，安装入口才打开相应商店页面。开发 ID 由 manifest 公钥推导；Native Messaging 仅允许该 ID 和已配置的商店 ID。

商店提交前仍需准备公开隐私政策 URL、说明/截图、权限理由、支持联系方式和独立安装步骤，并完成真实浏览器联调。具体是否通过审核由商店决定，当前 ZIP 不代表已上架或审核通过。

协议与验收清单见 [浏览器扩展接入](../docs/浏览器扩展接入.md)，数据说明见 [PRIVACY.md](PRIVACY.md)。
