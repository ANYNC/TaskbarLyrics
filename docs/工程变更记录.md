## 2026-08-13｜多显示器任务栏歌词与指定显示器选择

### 变更目的

让歌词窗口适配 Windows 多显示器桌面，并允许用户在全部显示器与指定一台或多台显示器之间切换，而不为每台显示器重复创建播放会话、歌词检索或音频采集服务。

### 用户影响

- 新安装和旧配置默认在所有已连接显示器的任务栏区域显示歌词。
- “显示与外观 → 窗口位置”新增显示器模式与多选列表，可指定一台或多台显示器；列表显示分辨率与主显示器标识。
- 显示器断开、连接、分辨率或排列变化后自动重建目标窗口。指定设备暂时断开且没有其他已选设备在线时，临时回退到主显示器；设备重新连接后自动恢复选择。
- 每台显示器独立应用任务栏边缘、虚拟桌面坐标与 DPI，支持位于主屏左侧/上方的负坐标显示器和混合缩放比例。

### 技术说明

- `LyricsWindowHost` 继续持有唯一完整 `MainWindow` 作为播放、歌词、封面和频谱状态源；其他目标显示器使用轻量 WebView 镜像窗口，并按有界状态槽接收 V1 歌词、封面、频谱和样式脚本。
- 显示器持久化使用 Windows 显示设备接口 ID，展示名称与当前 `DISPLAY` 编号不参与身份判断；模式切换仅触发歌词窗口布局重配，不重建歌词服务。
- 任务栏定位将目标显示器物理边界和工作区按该屏 DPI 转换为 WPF DIP，原生提交时再转换为物理像素，并识别上、下、左、右任务栏。
- 设置窗口和歌词宿主均监听 `DisplaySettingsChanged`，所有窗口访问继续位于歌词 STA Dispatcher 边界内；关闭时注销系统事件并释放镜像 WebView。

### 兼容性

- `settings.json` 新增 `LyricsDisplayMode` 与 `SelectedDisplayIds`；旧文件缺少字段或选择列表为 `null` 时规范化为“全部显示器”和空选择，不修改既有字段或枚举数值。
- WebView 继续使用 V1 `{ version, type, payload }` 信封；歌词 DOM、缓存格式、播放器识别、歌词检索和单曲偏移数据均无变化。
- 指定显示器列表保留暂时离线的设备 ID，使重新连接后能够恢复；运行时仅对当前已连接目标创建窗口。

### 验证

- Web 行为测试覆盖显示器模式渲染、指定多选消息与切回全部显示器；设置契约覆盖新增控件、持久化字段、热插拔监听和镜像调度入口。
- App 单元测试覆盖默认值、旧配置、空值与持久化、选择去重、大小写匹配、断连回退、负坐标、混合 DPI 和四种任务栏边缘。
- 完整验证通过：Web 29/29、App 132/132、Core 129/129、Settings 契约、格式检查、验证输出与重启脚本回归均通过。

### 后续事项

- 需在具有不同缩放比例、不同任务栏边缘及任务栏自动隐藏组合的真实多屏设备上人工观察 WebView 首次加载、热插拔恢复和歌词/频谱同步效果。

## 2026-08-12｜切歌封面过渡增加有界接管与读取超时

### 变更目的

修复切换歌曲后新封面未加载或缩略图流异常卡住时，上一首歌曲封面可能在整首播放期间持续显示的问题，同时保留新封面正常加载期间短暂沿用旧封面的自然过渡。

### 用户影响

- 切歌后的 1.5 秒内可继续显示上一首封面，避免立即闪烁为占位图。
- 超过过渡窗口仍未取得当前歌曲封面时，由当前播放器占位或匹配的本地封面接管，不再无限沿用上一首封面。
- 当前歌曲封面稍后成功加载时仍会立即接管；上一首歌曲迟到的异步读取结果不会覆盖当前歌曲。

### 技术说明

- 封面展示新增独立的有界过渡状态，以当前封面身份追踪请求和可见内容；封面身份优先使用 `SourceApp + SongId`，SongId 缺失时回退到 `SourceApp + Title + Artist + Album`，不使用可能在切歌期间波动的 Duration。
- SMTC 缩略图读取增加 5 秒超时；超时沿用既有缺图重试间隔，避免永久在途任务持续产生 `IsCoverLoading` 状态并阻止后续读取。
- 本地封面查询节流与 WebView 封面标识复用同一封面身份，不改变歌词的 `TrackInfo.Id` 或稳定身份。

### 兼容性

- 封面显示设置、WebView V1 协议字段、歌词检索、`settings.json`、缓存格式和用户数据均无变化。
- 同一专辑连续歌曲可以继续使用相同图片；封面归属按歌曲身份判断，不以图片字节是否相同作为拒绝条件。

### 验证

- `CoverTransitionStateTests` 覆盖 SongId 优先、专辑回退身份、空白规范化、过渡窗口截止和当前歌曲迟到封面接管。
- 完整验证通过：Web 28/28、App 114/114、Core 129/129、Settings 契约、格式检查、验证输出与重启脚本回归均通过。

### 后续事项

- 需在真实 QQ 音乐、网易云音乐等 SMTC 会话中人工验证正常快速加载、缺失 Thumbnail、卡住后重试和连续快速切歌的视觉表现。

- 原有验证失败仍以非零进程状态结束；完整日志位于既有忽略范围 `tmp/`，不会进入发布包。

## 2026-08-12｜版本标题的搜索召回与身份匹配完善

### 变更目的

完善 Remix、Live、Acoustic 和 `from …` 等版本或限定信息在破折号、括号等不同标题写法下的搜索召回、等价比较和冲突保护，避免同一版本漏搜或被不必要扣分，同时继续拒绝不同版本候选。

### 用户影响

- `Anti-Hero - ILLENIUM Remix`、`Versioned song – Live`、`Versioned song — Acoustic Version` 等标题会额外使用去除版本后缀的标题执行搜索，提高在线歌词召回率。
- `Anti-Hero - ILLENIUM Remix` 与 `Anti-Hero (Illenium Remix)` 等同版本标题可正确保留版本文字比较；给定示例的身份评分从 92 分提升至 98 分。
- `Nobody - from Kaiju No. 8` 与 `Nobody (from Kaiju No. 8)` 等同限定词标题可按完整限定词比较，示例身份评分提升为 100 分。
- Remix 与 Live、普通版等不同版本仍会在原始标题版本冲突检查中被拒绝，不会降低错误歌词保护。
- `Anti-Hero` 这类词内连字符、`Song - Chapter Two` 这类普通副标题及普通非版本括号内容仍维持既有保护或忽略规则。
- `from` 仅在一侧标题出现时沿用版本冲突保护；若后续诊断证明应视为同一曲目，再单独评估非硬冲突规则。

### 技术说明

- `LyricSearchPlanner` 新增 `version-relaxed-title` 查询变体，仅识别两侧带空格的 `-`、`–`、`—` 分隔符，并要求末段包含既有版本标记。
- 将搜索用规范化与评分标题用规范化分离：查询规划、艺术家和专辑继续移除括号内容；仅标题评分会对包含既有版本标记的括号内容去括号保留文字。
- 搜索变体与身份评估复用 `LyricMatcher` 的版本关键词单一来源；`from` 同时驱动原始标题冲突检查和括号内容保留，且冲突检查继续先于相似度计算执行。
- 宽松查询只影响候选召回，所有候选仍按原始 `TrackIdentity` 执行身份评分。

### 兼容性

- 不调整 80/95 分门槛、来源可信顺序、分段检索、Provider 适配器、缓存格式、设置或 WebView 协议。
- 仅影响受控版本后缀的查询召回，以及同一版本在括号、破折号等不同表达形式下的标题比较。

### 验证

- `LyricSearchPlannerTests` 覆盖三种破折号、普通连字符和副标题保护，以及宽松查询仍由原始版本身份拒绝约束。
- `LyricMatcherTests` 覆盖括号 Remix 等价、括号 Live 与 Remix 冲突拒绝、普通括号内容保持忽略、破折号/括号 `from` 等价为 100 分及单侧 `from` 冲突拒绝。
- 完整验证通过：Web 28/28、App 109/109、Core 129/129、Settings 契约、格式检查、验证输出回归和重启脚本回归均通过。

## 2026-08-12｜在线歌词音源分段变体检索

### 变更目的

避免 QQ 音乐、酷狗、网易云和 LRCLIB 对每首歌曲无条件串行请求全部搜索变体，降低正常歌曲的请求量与不稳定来源的连带失败概率，同时保留疑难标题的宽松召回能力。

### 用户影响

- 在线音源先以精确变体检索；只有本阶段没有达到既有身份录用门槛（80 分）的候选时，才继续后续规范化、主艺人、去除 feat/括号和版本后缀等变体。
- 正常歌曲命中精确查询后不再发出多余变体请求；疑难歌曲仍会按原有计划顺序尝试宽松查询。
- 版本冲突保护、95 分可信来源即时录用、跨音源并行、缓存、歌词抓取与用户设置均保持不变。

### 技术说明

- Core 新增内部共享分段执行器，统一按搜索计划顺序调用各音源的单变体检索，并始终以原始 `TrackIdentity` 评估候选。
- 发现可录用候选时仅返回当前阶段的首见去重候选；全部阶段均不录用时保留跨阶段候选，维持现有“身份拒绝”诊断语义。
- QQ、酷狗、网易云和 LRCLIB 复用该策略；直接 SongId 路径不进入分段检索。酷狗逐歌曲歌词候选查询和 150ms 重试保持原样。

### 兼容性

- `settings.json`、WebView V1 协议、缓存格式、音源可信顺序和持久化数据均无变化。
- 放宽查询仍不会绕过原始身份评分或 Remix、Live、Acoustic 等版本冲突拒绝规则。

### 验证

- `LyricSearchStageExecutorTests` 定向验证：6/6 通过，覆盖首个可录用阶段停止、候选全拒绝继续、累计候选回传、去重及异常/取消传播。
- Core 项目级验证：124/124 通过。
- 完整验证：Web 28/28、App 109/109、Core 124/124、Settings 契约、格式检查及验证输出脚本回归全部通过。
- `dotnet build TaskbarLyrics.sln`：0 警告、0 错误；`git diff --check`：通过。

### 后续事项

- 根据 QQ 等外部接口的真实耗时和失败诊断评估是否需要受控的阶段超时或并行补救；当前保持每个音源内的阶段顺序，避免增加请求突发。

## 2026-08-11｜确立 Sol 决策与 Luna 业务、测试编码执行模式

### 变更目的

将 Sol 主代理与 `luna_worker` 子代理的职责、委派条件、上下文交接和最终验收责任固化为仓库级工程规则，在保护 Sol 主线程决策上下文的同时，避免因微小任务、重复探索、完整历史复制或递归委派造成不必要的总 token 消耗。

### 用户影响

- 不改变 TaskbarLyrics 的运行行为、设置、歌词处理或用户数据。
- 后续边界明确的业务代码和对应测试代码原则上由 Luna 执行，Sol 负责需求与技术决策、拆分、审查、集成及最终验收。
- 微小改动、开放式决策和高度耦合任务不会为了使用子代理而机械委派。

### 技术说明

- 根级 `AGENTS.md` 新增 Sol + Luna 开发模式，明确 Luna 的业务代码、测试代码、局部重构和针对性验证职责，以及 Sol 的决策和交付责任。

### 用户影响

- 移除 DPI 回调中的同步强制布局，避免 WebView2 在新栅格化比例与旧控制器边界并存时进入不可恢复的裁切或隐藏状态。
- 每次锚定都以当前窗口 DPI 将完整逻辑边界换算为物理像素并提交给原生窗口，100%→150% 与 150%→100% 使用同一条边界更新路径，不会沿用切换前的物理尺寸。
- 任务栏定位改为读取主显示器物理矩形，并按歌词窗口当前 DPI 统一换算为 WPF 逻辑单位，避免运行时缩放后混用物理像素与 DIP。
- 若 WebView2 WPF 宿主无法暴露 DPI 栅格化控制器，或原生窗口物理边界提交失败，应用会写入一次可定位的 DPI 诊断；宿主仍通过 WPF DPI/显示设置事件执行基础刷新。

### 技术说明

- 根因一：自定义 `Program.Main` 未在创建 WPF `App` 前声明 DPI 感知，进程以 System DPI 模式运行；系统只能缩放启动时生成的位图，导致内容模糊且原生命中坐标错位。入口现在通过 `SetProcessDpiAwarenessContext(-4)` 显式启用 PerMonitorV2。
- 根因二：PerMonitorV2 生效后，Windows、WPF 与 WebView2 子 HWND 的 DPI 通知并非同时完成；同时 WPF `Height` 的逻辑值在切换前后均为 44 DIP 时不会重新提交原生高度，曾出现窗口 DPI 已降至 96、物理高度却仍保留 150% 下 66 px 的状态，窗口底部因此超出屏幕。
- `MainWindow` 通过线程安全的待处理标记合并 `OnDpiChanged`、`DisplaySettingsChanged` 与 WebView2 `RasterizationScaleChanged`，在 `DispatcherPriority.ContextIdle` 延迟执行完整刷新；浏览器确认自身栅格化比例变化后会再合并补充一次刷新。
