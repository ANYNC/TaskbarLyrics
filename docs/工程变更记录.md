## 2026-08-09｜翻译歌词改为原文与译文双行联动显示

### 变更目的

将原先追加在原歌词末尾的翻译迁移为稳定的双行布局，避免原文过长、逐词扫描和翻译内容互相争夺横向空间，同时保持无翻译歌曲的既有“当前句 + 下一句”体验。

### 用户影响

- 开启“显示歌词翻译”且整首歌词包含翻译时，第一行显示当前原文，第二行显示当前翻译；切换歌词时两行作为一组同步滚动。
- 检索完成并获得翻译歌词时，“正在检索歌词…”与空白第二行会作为旧双行单元连续滚出，首句原文与翻译从下方进入，不再直接覆盖检索提示。
- 某一行缺少翻译时第二行显示低强度单字符 `...`，不会临时切换为下一句，既保留双行节奏又避免与真实译文竞争视觉层级。
- 在线或本地歌词用 `//`、`///` 表示缺少翻译时，这些明确占位符会先按空翻译处理，再由翻译界面显示统一的省略号；整首歌只有占位符时仍会回到普通双行原文模式。
- 翻译使用与主色相同的 RGB 和主色 70% 的 alpha，在主歌词与普通次行之间形成稳定层级；翻译不参与逐词扫描和长歌词横向跟随。
- 关闭翻译或整首歌词没有翻译时，继续显示当前原文和下一句原文，原有逐词扫描、长歌词横向跟随和切行动画保持不变。

### 技术说明

- Core 的 `LyricDisplayFrame` 分别传递当前/下一句原文和翻译，并提供整首歌词级 `HasTrackTranslation` 标记；`LyricSyncService` 不再拼接翻译，也不再依赖展示设置，逐词进度始终按原文长度计算。
- `ParsedLyricLine` 在统一模型边界规范化空白及明确的斜杠翻译占位符，在线解析、本地歌词投影和旧解析缓存反序列化共用同一规则；包含斜杠的真实翻译文本不受影响。解析规范化版本提升为 `2`，旧 parsed cache 会失配并使用保留的 raw cache 重新解析。
- 缺译省略号只存在于 WebView 展示层，不写入歌词模型、缓存或 V1 消息；它使用翻译色并叠加 `0.55` 元素透明度，实际强度约为主色的 38.5%，不参与逐词扫描或横向跟随。
- App 将翻译开关收敛为纯展示变更，切换时不重建歌词同步服务或重新检索；WebView V1 `lyrics` payload 增量加入结构化翻译与 `translationMode`，样式 payload 增量加入 `translationColor`。
- WebView 将当前与待入场的“原文 + 翻译”双行单元置于同一轨道；切行时轨道连续上移两个行距，并复用普通切行的非线性缓动曲线，双行位移时长放慢为 760ms，普通模式仍保持 560ms；不再使用独立叠层交叉淡化，也不使用第二行晋升时的字号缩放；转场结束后清理临时 transform 和 `will-change`。
- 手动切换翻译设置时仍会取消在途转场并就地重绘当前帧，避免设置变化被误判为歌词切行；检索占位进入翻译结果则识别为内容转场并复用双行连续轨道。排队帧、逐词实时更新、降级动效和转场超时兜底继续保留。

### 兼容性

- `ShowLyricTranslation` 设置字段、默认值和持久化格式均未改变，不需要设置迁移。
- WebView 消息版本仍为 V1；新增字段均为兼容性增量，缺失时安全回退到普通双行显示。
- QQ 音乐、酷狗、网易云音乐的翻译获取与解析、歌词源选择、缓存格式、偏移和回退机制均未改变。

## 2026-08-09｜新增可开关的逐词双色扫描

### 变更目的

在保持现有字体、字号、字重、阴影、双行布局和切行动画不变的前提下，利用 QRC/KRC/YRC 等歌词中已有的逐词时间数据展示播放进度。

### 用户影响

- 设置“歌词 → 显示行为”新增“逐词扫描”开关，默认开启并即时生效。
- 存在逐词时间数据时，当前行初始使用第二行的次要颜色，已播放部分连续扫描为原有当前行颜色；第二行样式保持不变。
- 当前行歌词超出显示宽度且具备逐词进度时，扫描头到达视口约 65% 后会带动整行向左跟随，并在末尾停止；普通第二行和无逐词数据的歌词仍使用省略号。
- 关闭开关或歌词没有逐词数据时，当前行恢复原有整行高亮，不重新检索歌词。
- 暂停时扫描停在当前进度，拖动播放位置后按新位置立即重算。

### 技术说明

- Core 根据 `LyricSyllable` 的相对偏移、时长及其在原始歌词文本中的位置计算可空 `WordScanProgress`；英文空格等未包含在 segment 文本中的字符仍会映射回原句位置。
- App 仅在开关开启时把逐词进度加入歌词 WebView V1 payload；开关切换不会重建 `LyricSyncService` 或触发网络请求。
- WebView 使用现有 `--primary` / `--secondary` 颜色生成文字宽度内的裁剪渐变；进度为 `null` 时移除扫描状态，保留旧渲染路径。
- 切行期间的 promotion 状态实时消费同一句的最新逐词进度，扫描从翻滚开始即同步推进；下一句仍通过 queued frame 串行处理，不改变原有字号与位移动画。
- 晋升行从转场开始即使用第一行的原生字体度量，仅通过 `scale` 从第二行视觉尺寸过渡到 `1`，避免逐帧小数字号与转场结束重新栅格化造成清晰度和视觉字重跳变。
- 扫描显示使用两层普通 `color` 文字与互补硬裁剪，次色复用主色 RGB 并将 alpha 调整为主色的 60%，继续避免透明填充与 `background-clip: text`；播放时由 WebView 在相邻进度样本间执行 90ms 线性插值，暂停时立即移除插值并冻结在当前值。SMTC 在播放与暂停相互切换且时间线尚未刷新时会保留最后已展示位置，刷新后再接受真实播放、暂停或拖动位置，既避免暂停时回退到上一个逐词节点，也避免恢复播放时把暂停时长错误计入外推位置。静止时清理行/轨道 transform，并仅在转场期间启用 `will-change`，让第一行恢复与第二行一致的字体栅格化路径。
- 超长当前行的主色层和次色层共用一个裁剪视口与文字轨道；WebView 缓存自然文本宽度，以逐词进度估算扫描头位置，在视口 65% 锚点后计算受限横向偏移，并按物理像素对齐。连续播放只在短步进期间对位移执行 90ms 插值，暂停、跳播、换行、转场取消和进度缺失均立即定位或清理，不启用循环跑马灯。

### 兼容性

- `settings.json` 新增 `EnableWordScanning`；旧文件缺少字段时默认为 `true`，显式 `false` 可正常读取和保存。
- WebView V1 `lyrics` payload 仅新增可空 `wordScanProgress`，旧消息或无逐词数据时安全回退。
- 横向跟随完全复用现有 `wordScanProgress`，未增加消息字段；不溢出的歌词继续走原渲染路径。
- 歌词检索、音源选择、解析、缓存格式、翻译开关、偏移和频谱策略均未改变。

- 项目级验证：Web 21/21、App 94/94、Core 87/87、Settings 契约通过。
- `scripts/verify.ps1` 完整验证通过，包含 Web/App/Core、Settings 契约和格式检查。

## 2026-08-09｜修复 SMTC 分批更新时长导致歌词音源误选

### 变更目的

避免切歌时标题和歌手已经变更、Duration 仍短暂保留上一首歌曲时，正确候选因时长冲突被拒绝，并将错误音源结果锁定到整首歌曲。

### 用户影响

- 新歌出现后先等待 750ms 汇总同一轮 SMTC 元数据，再以最新的标题、歌手、专辑、SongId 和 Duration 发起歌词检索。
- 如果旧时长已经进入检索，而同一首歌随后出现达到匹配冲突阈值的有效时长修正，会取消旧请求、清除错误结果并自动纠正重检一次。
- 小幅时长抖动不会重复检索；同一首歌最多执行一次 Duration 纠正，避免播放器时间线波动造成循环刷新。

### 技术说明

- `LyricSyncService` 继续使用 `SourceApp + Title + Artist` 作为稳定可见歌曲身份；Duration 不进入身份键，避免时长波动被误判为切歌。
- 元数据稳定窗口结束时读取最新 TrackInfo，而不是捕获首次通知中的旧快照；纠正重检复用现有 CancellationTokenSource 和请求代次隔离，迟到结果不能覆盖新结果。
- Duration 纠正阈值与 `LyricMatcher` 的硬冲突阈值共用 `LyricMatchingPolicy.DurationConflictThreshold`，防止两套规则漂移。

### 兼容性

- 歌词源信任顺序、候选准入分数、缓存格式、映射、PreferredProvider、设置字段和 WebView V1 协议均未改变。
- `LyricSyncService` 原构造调用保持兼容；末尾稳定等待参数仅用于可控验证，默认值为 750ms。

### 验证

- Core 定向回归覆盖 242s→389s 在稳定窗口内合并、已开始检索后的单次纠正、旧结果隔离、小幅及重复时长变化不重检。

## 2026-08-08｜新增 Settings 歌词检索诊断页面

### 变更目的

### 用户影响

- Settings 新增“歌词诊断”页面；点击“开始诊断”后展示当前歌曲身份、搜索变体、四个在线来源的终态和候选列表；各来源默认展开并可独立折叠，候选仍完整保留。
- 每个候选显示标题、歌手、专辑、时长、候选 ID、查询变体、可公开的 fetch metadata 键名、匹配分、准入状态和拒绝原因。

- 每次锚定都以当前窗口 DPI 将完整逻辑边界换算为物理像素并提交给原生窗口，100%→150% 与 150%→100% 使用同一条边界更新路径，不会沿用切换前的物理尺寸。

### 技术说明

- `TaskbarPlacementService` 以 `GetDpiForWindow` 作为运行时缩放的权威值，同时更新 WPF 逻辑位置和 `SetWindowPos` 物理边界，消除 WPF `Height` 属性未变化时不会重新提交原生高度的问题。
- 删除冗余的 `SizeChanged → AnchorToTaskbar` 回调，避免锚定代码修改窗口高度时再次进入锚定流程。
- `TaskbarPlacementService` 使用 `MonitorFromPoint`/`GetMonitorInfo` 获取主屏物理边界，并在单一命名边界完成像素到 DIP 的转换；原 `SystemParameters` 路径仅保留为原生查询失败时的安全回退。

### 兼容性

- 进程 DPI 感知从 System 提升为 PerMonitorV2；固定 DPI 下的尺寸、锚点、置顶和显隐语义保持不变，变化集中在运行时 DPI 变更和多显示器 DPI 边界。

### 用户影响

- 原“外观”“窗口”两页合并为“显示与外观”页，侧栏导航 9 项降为 8 项；页内分“布局与封面”“文字样式”“窗口外观”“窗口位置”四个子面板。

- 歌词区域缩放现在同时管控窗口宽度：实际宽度 = 基础窗口宽度 × 缩放，并限制在屏幕工作区内；缩放预览新增“宽度”读数。
- “窗口宽度”从顶层控件下沉到“高级尺寸微调 → 基础窗口宽度”，改用滑块+数值组件，与其他基础尺寸一致。
- “恢复”改为“恢复 100%”，“恢复推荐比例”改为“重置基础尺寸”（后者现在一并重置基础窗口宽度）。

### 技术说明

- 新增 `AppSettings.ClampEffectiveWindowWidth(baseWindowWidth, scalePercent, maxWidth)` 与 `MinimumWindowWidth`/`MaximumWindowWidth`/`DefaultWindowWidth` 常量，集中宽度边界。
- `MainWindow.ApplySettings` 的宽度应用条件由 `WindowLayoutChanged` 扩展为 `WindowLayoutChanged || LyricsLayoutChanged`，使缩放变化也重算宽度；宽度按 `SystemParameters.WorkArea.Width` clamp，与现有主屏定位一致。
- `SettingsWindow` 将 `windowWidth` 纳入 `IsLyricsLayoutSetting` 与 `IsPreviewableSetting`，使基础宽度滑块支持实时预览并刷新有效宽度读数；`CreateLyricsLayoutPreview` 下发 `effectiveWindowWidth`。
- 设置页 `windowWidth` 控件由 stepper 改为 slider+number，复用通用滑块同步；`syncWindowBounds` 增加 windowWidth clamp 以校正越界输入。
- 设置契约测试 `$pages` 同步为 `displayArea`，并新增 `windowWidth` 滑块/数值对校验；web 测试的滑块计数由 6 改为 7。

### 兼容性

- `settings.json` 字段与默认值不变，无数据迁移；`WindowWidth` 仍为 [320,1400] px。默认缩放 100% 时实际宽度与旧版一致。
- WebView V1 信封、消息名、`window.settingsApp`、注入标记均未改变。
- 行为契约变更：缩放行的“窗口宽度…保持不变”承诺被显式替换为“窗口宽度随缩放等比变化”。
