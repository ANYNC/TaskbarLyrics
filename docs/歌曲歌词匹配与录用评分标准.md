# 歌曲歌词匹配与录用评分标准

本文说明 TaskbarLyrics 对在线歌词候选的身份评分、录用门槛、来源选择及分段检索规则。它描述当前实现，不替代 `LyricMatchingPolicy`、`LyricMatcher` 与 `LyricResolutionCoordinator` 中的代码约束。

## 1. 适用范围与基本原则

- 评分对象是播放器当前歌曲与在线音源返回的**歌曲候选**，不是歌词文本质量评分。
- 每个候选始终与原始 `TrackIdentity` 比较；即使检索时已放宽标题、艺术家或版本后缀，最终评分也不会改用放宽后的查询信息。
- 评分范围为 0～100 分，结果四舍五入为整数。
- 评分用于两个层次：候选是否允许抓取歌词，以及多个在线音源完成后的最终来源选择。

## 2. 评分前的硬性拒绝

以下情况直接记为 **0 分**，不会进入相似度加权：

1. 本地歌曲标题或远端候选标题为空，或等于 `Unknown Title`。
2. 标题的版本标记不一致。系统逐个比较下列关键词在本地标题和候选标题中是否出现；一方有、另一方没有即判定版本冲突：

   `live`、`remix`、`acoustic`、`demo`、`instrumental`、`karaoke`、`simlish`、`from`、`vma`、`award`、`现场`、`演唱会`、`颁奖`、`典礼`。

例如，本地曲目为 `Song - Remix` 而候选为 `Song` 时，候选为 0 分；放宽检索仅帮助召回，不能绕过版本一致性。

## 3. 字段规范化与相似度

标题、艺术家和专辑在比较前会执行下列规范化：

- 转换为简体中文、小写，并移除变音符号。
- 移除括号中的常见平台标签：`explicit`、`deluxe`、`digital`、`premium`、`album`、`edit`、`version`、`special`、`anniversary`、`studio`、`remastered`。
- 对艺术家、专辑及查询规划，移除其余括号内容；对**评分中的标题比较**，若括号内容包含 `remix`、`live`、`acoustic`、`from` 等既有关键词，则仅移除括号并保留内部文字。
- 移除末尾的 `feat.`、`ft.`、`with` 艺人后缀。
- 将标点归一为空格并合并连续空格。

标题、艺术家和专辑均使用 Jaro-Winkler 文本相似度。艺术家额外计算分词重叠相似度，取两种算法中的较高值。

时长相似度按秒计算：

- 差值不超过 1 秒：1.00。
- 差值达到或超过 10 秒：0.00。
- 中间区间按线性比例递减。

## 4. 基础加权公式

设标题、艺术家、时长、专辑的相似度分别为 `T`、`A`、`D`、`L`，均在 0～1 之间。基础分取决于可用信息：

| 可用字段 | 基础分 |
| --- | --- |
| 艺术家和时长均可用 | `0.50 × T + 0.30 × A + 0.20 × D` |
| 仅艺术家可用 | `0.60 × T + 0.40 × A` |
| 仅时长可用 | `0.75 × T + 0.25 × D` |
| 两者均不可用 | `T` |

若本地与候选专辑都不是空值或 `Unknown Album`，再混入 5% 专辑信息：

```text
最终相似度 = 0.95 × 基础分 + 0.05 × L
最终分数 = Round(最终相似度 × 100)
```

## 5. 候选录用与歌词抓取

| 分数 | 处理 |
| --- | --- |
| 0 分 | 身份冲突或标题无效，直接拒绝。 |
| 1～79 分 | 身份不够可信，拒绝。 |
| 80～100 分 | 身份录用，可按分数从高到低尝试抓取和解析歌词。 |

每个音源会先对候选评分，再按分数降序尝试歌词抓取。较高分候选没有歌词或内容无效时，会继续尝试该音源中其余已录用候选。

## 6. 在线来源选择与 90 分规则

默认在线来源可信顺序为：**QQ 音乐 → 酷狗 → 网易云 → LRCLIB**。各来源并行检索，但最终选择不是单纯的全局最高分。

1. 默认首选来源 QQ 音乐先完成且成功取得分数 **≥90** 的歌词时，立即录用并取消其他在线来源任务。
2. 否则等待所有在线来源完成。
3. 若完成结果中存在任一来源的 **≥90** 分歌词，仅在这些高可信结果中选择；若不存在，则在所有成功结果中选择。
4. 选择时先按来源可信顺序，再按身份分数降序。因此，来源可信顺序是主要优先级，分数是同一优先级下的比较依据。

这意味着 90 分是“高可信集合与首选来源快速返回”的界线；80 分才是单个候选可参与后续歌词抓取的最低身份门槛。

## 7. 分段式搜索变体

在线音源不再无条件请求所有变体，而是按搜索计划顺序分段执行：

1. `exact`：原始标题与完整艺术家信息。
2. `normalized`：规范化标题与艺术家。
3. `primary-artist`：仅主艺术家。
4. `relaxed-title`：移除括号或 `feat.` 等后缀的标题。
5. `version-relaxed-title`：仅在受控版本后缀场景下移除 ` - Remix`、` - Live`、` - Acoustic` 等后缀。

每个音源在一个阶段发现任一 **≥80 分** 候选后，停止该音源的后续变体请求；当前阶段候选按候选 ID 首见去重后，交给既有歌词抓取流程。若整个阶段没有可录用候选，才继续下一变体。所有阶段均无可录用候选时，系统保留跨阶段候选，以输出“身份拒绝”而不是“没有候选”的诊断。

直接使用官方音源 `SongId` 的场景不执行变体检索，仍使用原始歌曲信息构建候选并进入既有的歌词抓取流程。

## 8. 诊断与维护要点

- 诊断日志会记录候选的 `QueryVariant`、身份是否录用及 `IdentityScore`，最终录用日志也会保留来源、候选 ID、变体和分数。
- 修改评分权重、版本关键词、80/90 门槛或来源可信顺序时，必须同步更新本文件、相关单元测试与工程变更记录。
- 不应为了提升召回率而让宽松查询绕过原始身份评分；这会使普通版、现场版和 Remix 等不同版本错误共用歌词。

## 9. 实现位置

- `TaskbarLyrics.Core/Utilities/LyricMatcher.cs`：字段规范化、相似度和版本冲突。
- `TaskbarLyrics.Core/Services/LyricIdentityEvaluator.cs`：候选录用（80 分）。
- `TaskbarLyrics.Core/Services/LyricMatchingPolicy.cs`：80 分、90 分与超时常量。
- `TaskbarLyrics.Core/Services/LyricSearchStageExecutor.cs`：分段变体检索停止规则。
- `TaskbarLyrics.Core/Services/LyricResolutionCoordinator.cs`：跨来源并行、90 分即时录用及最终来源选择。
