# 临时歌词布局日志收集

用于一次收集歌词裁切和播放控制面板无法触发的现场数据。不修复或放宽现有布局、点击校验，不添加设置字段或 WebView 消息类型。

## 构建和启用

普通构建不附带启用标记。临时版使用 `dotnet publish TaskbarLyrics.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:LayoutDiagnostics=true -o publish/layout-diagnostics`。将整个输出目录打包交给用户，保留 EXE 旁的 `layout-diagnostics.enabled`。也可以在已有兼容版本的 EXE 旁放置该标记文件后重启；仅本次新增诊断功能的版本识别它。

每次启动生成一个 `Logs/layout-diagnostics-时间-进程号.jsonl`，主窗口和所有镜像窗写入同一文件。安装目录不可写时回退到 `%LOCALAPPDATA%\TaskbarLyrics\Logs`；普通 `app_debug.log` 的 `LAYOUT_DIAGNOSTICS` 项也记录实际文件位置。删除标记文件并重启即可关闭。标记不会修改或删除用户设置。

## 用户操作

1. 完全退出原来的 TaskbarLyrics，解压临时版到可写目录后启动，开始播放有歌词的歌曲。
2. 保持系统显示缩放 150%。将应用的整体缩放设为 100%，等待 3 秒，在封面和歌词区域分别按当前配置点击或悬停，尝试打开面板。
3. 将应用整体缩放调到 30% 以下，等待 3 秒，再重复触发操作；如果方便，也切换一次浮窗和嵌入模式进行对比。
4. 在启动后的 10 分钟内完成操作。退出应用，将本次生成的一个 `layout-diagnostics-*.jsonl` 发回，并说明哪一档能打开面板。

## 数据和限制

- 记录环境版本、系统文字缩放，目标显示器／工作区、真实任务栏父窗口矩形，窗口 DPI 与感知模式、WPF 元素尺寸及屏幕边界，WebView 控制器 bounds／rasterization scale／zoom 和网页 viewport／DPR。
- 网页记录封面、两行文字及各层裁切容器的矩形、CSS 字号／行高／溢出状态、字体加载状态，以及点击／悬停事件。只读取几何和样式，不读取歌词正文、歌曲元数据或封面 URI。
- 宿主记录面板触发消息的数字边界、校验结果和拒绝原因，以及面板打开路径的分支。原有 V1 消息和拒绝规则保持不变。网页队列每秒读取一次；队列上限 24 条，丢弃数会写入日志。
- 每个歌词窗最多采集 10 分钟，统一文件最多 2,500 条／16 MiB。每次采样执行超时为 3 秒，不重叠执行；关闭窗口会取消等待、停止计时器。
- 需要问题在本次运行中复现。未收到网页点击、但鼠标处于封面范围时，可结合 `windowUnderCursorClass` 与 WPF 命中区域判断事件是否被其他窗口或原生透明区域截走。面板的 `PanelShowRequested` 表示开始请求打开，下一份主窗快照的 `PanelVisible` 用于确认是否实际可见。
