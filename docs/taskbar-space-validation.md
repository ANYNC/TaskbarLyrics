# 横向任务栏避让：验证记录

## 范围与复现

基线：`eb3294b7469dcba72fec3b236725b745185c4703`。Windows 11 横向嵌入模式原先只把歌词窗口限制在整条任务栏内；当居中图标增多、搜索框占用变大，或歌词窗口宽度超过剩余空白时，长歌词会绘制到开始、搜索及应用按钮上。

合入时根据用户确认的定位策略调整：先按配置宽度、锚点和偏移计算并限制期望起点，只使用起点所在的连续空白区，保留 8 DIP 间距并向右限制实际窗口宽度；不跨图标组选择其他空白区，也不向左移动以扩大宽度。起点被占用、右侧不足 100 DIP，或没有可用的新鲜几何快照时，原生歌词表面临时缩为零，空间恢复后在原位置恢复；不改写用户配置宽度。浮窗、Windows 10 与竖向任务栏的既有定位路径不应用此横向策略。100 DIP 是独立的最低显示宽度策略，不是根据字形测量得出的可读性保证，也不改变设置字段的宽度下限。

与 PR #37 的关系：该 PR 新增可选的“自动跟随图标”锚点和过渡动画；本次修正现有左/中/右锚点的嵌入窗口边界，不增加设置项、枚举值或动画。

缓存测试覆盖首次异步读取、时间戳为零、500 ms 节流、单个在途查询、null／COM／元素失效、查询开始时间计龄、两秒过期、句柄／矩形切换、切回原目标时拒绝旧结果、取消与退出后迟到结果。100%／125%／150%／200% 和负坐标由自动回归覆盖。

提交后自查发现，解绑或传入无效原生目标时，旧快照及在途读取的代次未立即失效；如果很快恢复同一 HWND 和矩形，就可能沿用旧范围。本次补充六项回归，修复前全部失败，修复后全部通过。解绑、零 HWND 或无效矩形现在会清除快照、递增代次，拒绝此前读取的迟到结果；旧读取结束前仍不启动第二个查询，之后恢复目标时可立即重读，无需再等节流周期。完整 App 复验仍仅有上述四项基线失败，未出现新的失败。

原生自查还复现过图标增加后安全间距暂时不足：歌词右边界 315 px、按钮左边界 321 px，实际间距 6 px，未达到预留的 10 px。后台已完成的快照原先还要等下一个定时器才应用；现在只有当前目标、当前代次的有效读取才发出通知，在歌词所属 Dispatcher 排队立即更新位置，保留 500 ms 读取节流。既有用例补充了成功通知、失败不通知、失效／退出后迟到结果不通知的断言，锚点退出时解除订阅。

## 可重复运行的原生检查

```powershell
dotnet run -c Release --project TaskbarLyrics.Diagnostics -- --taskbar-space verify
dotnet run -c Release --project TaskbarLyrics.Diagnostics -- --taskbar-space benchmark 15
```

原生检查使用实际生产定位器和读取器，并临时创建透明窗口及一个自动关闭的最小化任务栏图标。检查图标出现／关闭时的动态边界、空间耗尽后恢复、负坐标父窗口，以及竖向定位绕过横向检测。它不启动音乐服务，不访问用户配置数据库，不重启 Explorer，也不更改任务栏设置。

初次 Release 原生检查五个阶段通过，实际歌词宽度为 366→312→366 px。提交后自查保留了上述间距不足的失败记录，并将诊断读取移出 Dispatcher、在读取后采样实际窗口边界，间距断言未放宽，失败信息包含阶段、读取耗时及控件范围。通知修复后连续五轮、每轮五个阶段全部通过：图标增加时宽度为 366→311 px，关闭图标后采样为 364–366 px。增加实测间距输出后再次校验，三种状态分别测得 10、10、11 px。名义间距为 10 px，原生断言保持既有的 1 px 舍入容差，报告分别输出目标与实测最小间距；隔离父窗口中验证了零面积隐藏、负坐标下恢复，以及 60 px 宽竖向定位不启动横向读取器。

性能命令交替运行六组相同节奏的客户端试验：保留调度器但不查询 UIA、原始宽泛子树查询、Explorer 子树查询，再反向重复；每组 15 秒。先核对两个读取器识别的占用区域一致。输出成功查询次数、尝试次数、临时错误类型、查询延迟、客户端 CPU 和分配量；临时错误不从报告中抹除。

这里的 CPU 仅属于诊断查询客户端，按逻辑处理器数量归一化。它不代表整个歌词应用、Explorer 服务端、GPU、游戏帧率或电池续航的净变化。延迟包含跨进程等待，桌面负载会使结果变化，不据此承诺固定收益。

## 仍需在其他设备复核

- 本机没有第二个物理显示器；负坐标和不同缩放的计算已有自动及原生父窗口检查，但不能替代真实混合 DPI 多屏切换。
- 未实际重启用户的 Explorer；句柄、矩形、失效读取和迟到结果已通过可控故障验证。
- 未在真实 Windows 10 或第三方修改的任务栏上测试。Windows 10 和竖向定位分支保持原路径；原生检查验证了竖向绕过，不代表所有第三方任务栏兼容。
- 500 ms 检测存在响应间隔。暂时读取失败时最多沿用两秒内的匹配快照，随后隐藏；单次未返回的原生调用不会造成查询堆积或阻塞歌词调度线程。
