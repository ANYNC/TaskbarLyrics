# 界面本地化：代码与语言文件结构

本文说明 TaskbarLyrics 界面本地化的两层结构（代码层与语言文件层）、语言文件如何被检测与加载、以及当前特殊处理的系统语言重定向。文案风格与 WebView 页面规则见[WebView 界面视觉与交互规范](WebView界面视觉与交互规范.md)第 7 节；功能级变更需要同步[工程变更记录](工程变更记录.md)。

## 1. 总览

- 本地化分两层：**语言文件层**只承载语言数据，**代码层**负责加载、取词、注入网页、应用用户偏好。
- **语言列表完全取决于语言文件**：有哪些语言、顺序、各语言自称都只在 `TaskbarLyrics.App/text.yaml` 维护；代码、设置页和其它配置都不保存语言列表，也不存在语言 ID 白名单。
- 系统语言先经检测映射到语言文件中的语言 ID，再叠加用户持久化偏好。

## 2. 语言文件层结构

唯一的语言文件是 `TaskbarLyrics.App/text.yaml`，作为嵌入资源随程序集发布（逻辑资源名 `TaskbarLyrics.App.text.yaml`）。

**语言列表的唯一维护点**：语言列表（存在哪些语言、它们的顺序、各自名称）只由本文件决定，并且只在本文件维护；增删一个语言段就等于增删设置页的一个语言选项，不需要改动代码或其它配置。代码中不存在独立的语言列表常量、配置文件或语言 ID 白名单。

```yaml
Zh-CN:                    # 语言 ID，同时是目录段的键，也是设置项/持久化使用的值
  LanguageName: "简体中文"  # 段内第一项，固定字段：该语言的自称
  UI_Pause: "暂停"         # 其余为语义键
  UI_PlayingDemoS: "正在演示 · {0} 秒"
EN:
  LanguageName: "English"
  UI_Pause: "Pause"
```

- **字段顺序**：`LanguageName` 固定为每段第一项；其余键顺序不影响取词，但建议保持三语言顺序一致，便于 diff。
- **段顺序**：语言段的先后顺序就是设置页语言选项的顺序，也是语言清单的顺序来源。
- **键空间**：键名带域前缀（`UI_`、`Update_`、`Lyrics_`、`Display_`、`Hotkey_`、`Font_`），语义稳定，不随语言变化。
- **占位符**：统一 `{0}`、`{1}` 形式；同一键在多个语言中的占位符必须一致，由测试校验。
- **缺失键**：C# 取词回退为键名并只记录一次警告；网页侧回退为键名本身。
- **语言元数据**：`LanguageName` 是该语言的自称，供设置项显示；`UI_InterfaceLanguage` 是“语言设置项”的标题，格式由语言文件强制指定为 `<本地化的“语言”>\Language`（英文语言下只写 `Language`）；`UI_AutoDetect` 是“自动检测”选项文案。这三类文案都不在代码中拼接。

## 3. 代码层结构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 数据加载与取词 | `TaskbarLyrics.App/Text.cs` | 读取嵌入的语言文件并反序列化为 `语言 ID → 键 → 文案`；`T()`/`Format()` 取词与格式化；`CreateWebBootstrap()` 把当前语言的文案与 `text.js` 拼成网页引导脚本。 |
| 语言清单 | `Text.cs` 的 `Languages` | 从语言文件中按段顺序发现语言段，读取各自的 `LanguageName`，得到 `(Id, Name)` 清单。 |
| 语言检测 | `Text.cs` 的 `DetectSystemLanguage()` | 把系统 `CultureInfo` 映射为语言 ID（见第 4、5 节）。 |
| 偏好归一 | `Text.cs` 的 `NormalizeLanguagePreference()` / `ResolveLanguage()` / `ApplyPreference()` | 把持久化值归一为语言文件里存在的 ID 或空值（自动检测），并应用为进程当前语言。 |
| 网页运行时 | `TaskbarLyrics.App/text.js` | 读取注入的 `window.taskbarLyricsLocale`，提供 `window.taskbarLyricsI18n`（`language`、`locale`、`t()`、`format()`、`translateDocument()`），替换页面中的 `{{UI_Key}}`、设置 `<html lang>`。 |
| 持久化模型 | `AppSettings.UiLanguage`、`SettingsStore.cs` | 保存/加载用户选择；加载时把缺失、空值或未知 ID 归一为自动检测。 |
| 启动应用 | `App.xaml.cs` | 创建任何窗口前调用 `Text.ApplyPreference(Settings.UiLanguage)`；保存设置时检测语言变化并触发即时切换。 |
| 设置页宿主 | `SettingsWindow.xaml.cs` | `settingsState` 载荷包含 `settings`、`fonts`、`uiLanguages`（由语言清单派生，首项为自动检测）；处理 `update/uiLanguage`；刷新语言时重载网页并保持当前 tab。 |
| 设置页网页 | `Web/Settings/settings.js`、`settings.html`、`settings.css` | 渲染语言选项、提交选择；重载时先隐藏页面区，按宿主注入的目标 tab 首帧渲染后再显示。 |
| WPF 界面 | `*.xaml` / `*.xaml.cs` | 静态文案用 `{local:Translate Text='UI_Key'}`，运行时文案用 `Text.T()` / `Text.Format()`。 |

网页侧只消费宿主注入的数据：语言 ID 与文案字典由引导脚本在文档创建阶段写入，页面脚本运行时读取；设置页的语言选项来自宿主下发的清单，网页不自行发现语言。

## 4. 语言文件的检测与加载逻辑

1. `Text` 首次使用时读取嵌入资源 `text.yaml`，用 YamlDotNet 反序列化为 `Dictionary<语言 ID, Dictionary<键, 文案>>`；反序列化失败或资源缺失会在启动阶段直接暴露为异常/日志，而不是静默降级。
2. 语言清单 `Languages` 另走一遍**行级扫描**，而不是依赖字典顺序：按文件顺序匹配顶层段头（`^语言ID:$`），再要求该段在目录中存在且包含非空 `LanguageName`；不满足的段被跳过。因此清单顺序严格等于文件书写顺序，与 YAML 反序列化的字典顺序无关。清单完全由语言文件派生，代码中不存在独立的语言列表。
3. 清单用于：设置页 `uiLanguages` 载荷、`NormalizeLanguagePreference()` 的合法性判断、`ResolveLanguage()` 的偏好解析。
4. 偏好的解析顺序：持久化值归一后非空 → 直接作为当前语言；否则用 `DetectSystemLanguage(CurrentUICulture)`。
5. 当前语言只影响取词与网页引导脚本；切换语言时重新生成引导脚本并重载相应网页，不重建语言文件缓存。
6. 新增/删除语言段时清单自动跟随；若新语言需要参与系统语言自动检测，必须同步更新 `DetectSystemLanguage()` 的映射（见第 5 节），因为检测映射是代码层的策略，不从语言文件推导。

## 5. 当前特殊处理的语言重定向

`DetectSystemLanguage()` 沿 `CultureInfo.Parent` 链检查，命中即返回；未命中时按语言名判断：

- 繁体中文的地区变体统一重定向到同一个通用繁体目录，不拆分地区目录：`zh-Hant`、`zh-Hant-HK`、`zh-Hant-MO`、`zh-Hant-TW` 以及旧式 `zh-CHT` 都映射到 `Zh-Hant`。
- `zh-CN` 映射到简体目录；其余语言映射到英文目录。
- 用户选择的固定语言优先于上述检测；`UiLanguage` 为空或未知 ID 时回到系统检测。
- 通用繁体以台湾用语为基线（設定、預設、工作列、滑鼠、浮動視窗等）；按产品决定，港澳市场用词差异暂由该目录承担。若将来需要地区目录，应在语言文件中新增对应语言段，并在检测与网页 `locale` 映射中补充对应分支。

## 6. 设置项与运行时切换

- 设置 → 常规 → 应用界面 的“界面语言”选项：首项“自动检测”（`value` 为空），其后按语言文件顺序列出各语言自称；选项来自宿主，网页只渲染。载荷缺少清单时该项隐藏。
- 选择通过 V1 `update` 消息提交（`key: "uiLanguage"`），写入 `settings.json` 的 `UiLanguage`；缺失、空值或未知 ID 在加载时归一为自动检测。
- 切换立即生效：更新进程语言后重载设置页、歌词主窗与镜像窗、SMTC 监视器、频谱调参的网页内容，关闭已展开的嵌入控制面板；设置页重载时按宿主注入的目标 tab 首帧渲染，避免闪回默认页；托盘菜单在下次打开时使用新语言。
- 启动阶段在创建窗口前应用语言，因此首帧即为目标语言。

## 7. 维护约定

- 语言列表只在 `TaskbarLyrics.App/text.yaml` 维护：增删语言段即可增删语言选项，不要在代码、文档或其它配置里另建语言列表；只有系统语言自动识别与网页 `locale` 需要时，才在代码的映射中补充分支（映射是“文化名 → 语言 ID”的规则，不是语言列表）。
- 修改文案时三语言段同步加键，不在代码或页面中写死中文；占位符保持一致。
- 页面静态文案用 `{{UI_Key}}`，动态文案用 `t()`/`format()`，WPF 用 `{local:Translate}` 或 `Text.T()`。
- 相关测试：`tests/web/localization.test.js` 校验键集合、占位符、渲染与缺失回退；`TaskbarLyrics.App.Tests/LocalizationTests.cs` 校验系统语言映射、目录读取与引导脚本；`tests/web/bridge.test.js` 校验设置页语言项；`TaskbarLyrics.App.Tests/UiLanguageSettingsTests.cs` 校验语言文件自描述、偏好归一与持久化。
- 定向验证：`scripts/verify.ps1 -Tier Targeted -Area App -Filter FullyQualifiedName~Localization`（或 `~UiLanguage`）、`npm run test:web -- tests/web/localization.test.js`；完整验收使用 `scripts/verify.ps1`。

## 8. 已知限制

- 通用繁体是台湾用语的通用基线，港澳用词差异按产品决定暂不细分；人工校对与地区目录属于后续工作。
- 语言文件同时承载语言元数据与界面文案；若目录规模显著增长，可评估拆分资源文件，但需同步调整 `Text.cs`、网页测试辅助与键一致性测试。
- 已打开的辅助 WPF 窗口（如浮窗播放面板）只有标题/无障碍名称可能延后到下次打开才更新。
- 极端缩放与最小窗口下的布局验收、真实界面人工巡检尚未执行。
