# 浏览器扩展：采集范围与开发交接

范围确认日期：2026-10-30；通用优先路线更新：2026-10-31。本文面向继续开发扩展和桌面桥接的维护者，包含用户已确认的目标范围、当前代码基线、已知问题与复现证据。换环境继续开发时先读本文，再按实际代码确认状态。

**当前开发基线为扩展 0.2.7、V1 信封与可选媒体详情版本 1；上一完整实机基线为 0.1.2。** 2026-11-02 已确认 0.2.5 可在 Edge 运行，封面链路通过 fake-IP 修复恢复；随后用 Chrome DevTools MCP 直接读取 Spotify 页面，确认页面只有静音短视频、真实音频走 Web Audio，探针在静音期间只能报 metadata-only。0.2.6 尝试增加通用 Web Audio 播放证据，但 MCP 未捕获到 Spotify 主页面上的上下文；0.2.7 改用 Web Scrobbler 的标签页 audible 思路，只在页面声明 unknown 时提供播放证据，不提供位置或时长。桌面同时修正“无效其他来源不得清空有效 Browser 候选”的回退；仍需用户更新 0.2.7、刷新 Spotify 并关闭其他播放器后实机验收。Spotify 的 0.2.4 诊断确认多数有效媒体未进入“有限时长 AUDIO”分类，仍无时间轴；0.2.5 统一处理原生音视频和开放时长，待新包实机确认。用户反馈网易云网页现可采集歌曲信息，其他能力未完整确认。历史成功或模拟结果不等于新版本实机通过。

### 2026-11-02 0.2.6 Web Audio 播放证据与桌面回退

- Chrome DevTools MCP 实机证据：0.2.5 下 Spotify 的 `MediaProbe` 曾显示 `Source=associated-element Playing=true HasDuration=true Association=media-state DeclaredState=none SelectedTag=VIDEO`；页面实际只有一个 7～8 秒静音视频，真实音频走 Web Audio。静音期间探针只能报 `media-session Playing=false`，有效 Browser 元数据随后被暂停／异常的 Netease SMTC 挤掉，3 秒无播放计数后自动隐藏。页面刷新可使会话恢复；应用重启或扩展重载后旧 relay 反复抛 `Extension context invalidated`，因此刷新媒体页面仍是必要步骤。
- 0.2.6 在 MAIN 环境通用观察 `AudioContext`／`webkitAudioContext` 构造；运行中且 `currentTime` 前进的上下文仅作为播放证据，在 Media Session 为 none／unknown 且存在标准标题时保持 `playing`，位置和时长继续为 null，不伪造时间轴。测试新增运行／挂起 AudioContext 夹具；Web 6 个文件 59 项通过，脚本语法、ZIP 13 个运行文件、原始路径和源码哈希通过；包为 `tmp/browser-extension/TaskbarLyrics-Browser-0.2.6.zip`。MCP 复核 Spotify 主页面仍显示 `media-session Playing=false`，未捕获到其 Web Audio 上下文；夹具通过不等于该站修复，若上下文在其他 frame／realm，需另行评估通用跨文档关联或网站专用模块。
- 桌面 `SmtcSessionReadBoundary` 增加可用性判断：其他播放器快照不是有效歌曲时，回退到仍然有效的 Browser 候选，而不是把有效歌曲清成 NoPlayback；可用暂停来源仍按既有优先级保留。App 定向 17 项通过，零警告构建通过；新增 `SessionAccepted`／`SessionExpired` 有界诊断（5 秒节流）以区分会话到达与会话过期。
- 仍需用户更新 0.2.6 并刷新 Spotify；测试前暂停／关闭 Netease 等其他播放器。定位期间可暂时关闭“无播放时自动隐藏”，让最后的歌曲标题和封面留在显示区；这不会恢复时间轴或控制能力。真实 Spotify 的显示保持、歌词未知进度和逐项控制仍待实机验收，不能把夹具或 MCP 观察写成用户问题已解决。

### 2026-11-02 0.2.7 标签页 audible 播放证据

- 社区方案核对：Web Scrobbler 的 `useTabAudibleApi` 每秒读取标签页是否发声来判断播放；KDE Plasma Browser Integration 使用媒体元素事件 + Media Session shim，并忽略有限时长小于 8 秒的媒体；WebNowPlaying 的 Spotify 模块依赖 React 私有 `PlayerAPI`，Web Scrobbler 的 Spotify 连接器使用播放条 DOM 时间选择器。没有项目用纯通用接口同时得到 Spotify 的准确位置和时长。
- 0.2.7 在 worker 的 `onMessage` 中读取浏览器提供的 `sender.tab.audible`；仅当 `details.playbackState === "unknown"` 时把它作为播放证据，设置 `playbackState=playing`/`isPlaying=true`。显式 paused／ended 不覆盖，位置和时长继续为 null，不伪造时间轴。这样静音视频、Web Audio、iframe 场景只需标签页仍在发声即可保持 Browser 候选；不增加协议字段。
- 验证：Web 6 个文件 60 项通过（新增 audible unknown／非 audible／paused 夹具）；worker 测试、media-probe 语法、ZIP 13 个运行文件、原始路径与源码哈希、`git diff --check` 通过。包为 `tmp/browser-extension/TaskbarLyrics-Browser-0.2.7.zip`。重载 0.2.7 后 MCP 仍记录 `SessionAccepted ... Playing=False`：worker 的 `chrome.tabs.get` 没有观察到 `audible=true`，或页面详情不是 `unknown`，因此该路径尚未在 Spotify 实机生效。必须先确认 Spotify 播放设备是“此网页浏览器”且标签页未被静音；若 `tab.audible=false`，浏览器没有提供可靠播放证据，通用层无法单独解决。
- 仍未解决：Spotify 的歌词进度和准确拖动需要站点专用 DOM 时间选择器或私有 API；本轮没有引入站点专用模块。更新 0.2.7 后仍需刷新 Spotify、暂停／关闭其他播放器，并确认 `SessionAccepted ... Playing=True` 与显示区保持。

以下为 0.2.2 通用能力增量与已有证据：

- 用户明确要求先吸收 WebNowPlaying 的通用采集方式，测试通用能力范围后再评估网站专用模块。本版没有网易云或其他网站专用选择器、没有网站适配模块，也没有扩展与 SMTC 自动关联补充；协议、设置与权限范围保持。

- 无标准元数据时依次读 og:title、meta[name=title]、document.title；清理播放符号，仅识别明确的 `, by`／`by:` 歌手分隔；不把网站名或普通连字符当作歌手，切歌不残留上一首推断歌手。封面依次为标准 artwork、已选视频 poster、单一有效媒体文档的 og:image，均复用 HTTP(S) 地址验证和原桌面读取边界。未就绪媒体不成为候选，直播不虚构总时长或下一首动作。

- 通用模拟覆盖背景视频干扰、关联媒体前后跳转、同任务中位置先于元数据更新、未知位置、旧曲目控制、处理器拒绝／无效果／超时、目标文档关闭、旧协议兼容、封面边界和两种控制面板状态。最新定向结果：Web 23、App 50、Core 19 项通过；解决方案构建零警告零错误。日志在原环境忽略目录 tmp/verify-logs/browser-generic-*。
- 仍需实际页面复验，尤其是用户那次网页拖动异常、网易云网页能力、休眠及多配置文件。没有可靠关联元素且网页不及时调用 setPositionState 时，目前无法从标准 API 读回内部跳转位置；不以固定等待时间猜测进度。

### 0.1 通用能力范围与实测安排

参考项目的 [Spotify.ts](https://github.com/keifufu/WebNowPlaying/blob/main/src/extension/content/injected/sites/Spotify.ts) 自身属于专用模块：状态、进度与控制依赖页面 React 容器中的私有 PlayerAPI／PlaybackAPI，歌曲及封面读取 Media Session。因此参考项目支持 Spotify，不能直接证明其 Generic 模块能完整覆盖 Spotify；本项目当前不采用这些私有接口，仍按用户要求先测试通用范围。

| 来源／场景 | 当前通用行为 | 证据边界 |
| --- | --- | --- |
| 标准 Media Session 元数据与 setPositionState | 保留歌曲、封面、声明状态和时间锚点，处理速率与暂停 | 已有夹具通过；真实拖动需复验 |

| 多媒体无标准歌曲信息 | 优先未静音有效媒体并保持当前播放候选；歧义时不随意取第一个；页面级图片不跨媒体拼接 | 夹具覆盖主要边界，复杂广告／切源需实机 |
| 仅页面元标签、没有媒体 | 不生成播放候选 | 夹具通过 |

| 纯 Web Audio、封闭自定义播放器 | 若提供 Media Session 可保留其信息，否则无可靠通用歌曲／时间轴 | 尚未实机确认，不承诺覆盖 |
| DOM 私有播放器文字、网站 API 或内部状态 | 当前不读取，不把这类能力混入通用实现 | 待通用验收后评估适配必要性 |

真实页面按 Spotify → 网易云当前播放器 → Bilibili／飞牛等不同实现逐项记录：歌曲／歌手、封面、自然切歌、暂停恢复、网页前后拖动、桌面拖动和逐项控制。每个结果记录版本、origin、时间与来源，标为“通过／字段缺失／失败／工具未能采样”。Spotify 0.2.2～0.2.4 初步结果见本节顶部，0.2.5 待新包验收；网易云先前“未监听到”和后续“可采集歌曲信息”均为用户观察，未能单独说明完整能力或原故障根因。诊断工具曾阻止其站点采样，不能绕过或以夹具替代实测。

只有在上述矩阵形成实际证据后，才评估网站专用模块；当前不以“未显示”直接推导“必须接入网易云适配”。

## 1. 产品目标与既定行为

扩展是通用网站媒体信息桥接器，为本机 TaskbarLyrics 提供网站识别、歌词同步、封面与定向媒体控制。Spotify、网易云网页、Bilibili、飞牛音乐等都是验证对象；单一网站的行为不能作为全部网页播放器的契约。

- 浏览器播放器卡片继续默认关闭。添加网站只启用网站识别模式，不自动打开播放器识别总开关。
- 未配置或关闭网站识别模式时，沿用原来的浏览器 SMTC 监听。
- 网站模式开启且扩展健康时，仅用户配置、启用且已授权的精确 origin 参与。未列入的网站不参与候选选择。
- 正在播放优先，再按网站顺序；同网站、同播放状态时标准媒体标题优先于页面标题备用信息，同等质量保留当前候选。选出的浏览器会话继续参与桌面已有播放器优先级与播放状态选择。
- 扩展断连按约定回退到原来的通用 SMTC 监听，恢复并确认配置后重新使用网站规则。健康空列表、无媒体、信息缺失或缺少单站授权不触发无限制回退。
- 浏览器负责安装、网站权限的最终确认。当前安装入口准备本机通信并打开开发包目录，商店正式安装尚未接入真实商店 ID。
- 当前同仓独立目录维护，扩展独立版本与打包。将来拆仓需要同步协议及兼容测试，不能依赖本机未提交文件或聊天记录。

### 2.1 数据与功能边界

- 采集仅发生于用户配置、启用且获授权的网站。随机配置文件 ID 仅用于本地路由，不采集浏览器账号或用户身份。
- 每个字段允许缺失。未知位置不等于真实零秒，未知时长不等于零长度，未知控制能力不等于支持。0.1.2 的零值／布尔编码不满足完整目标语义，演进时需要明确兼容处理。
- 网站身份仅需 origin（协议、域名、端口）。浏览器内部可为授权与来源匹配临时读取页面地址并提取 origin，但不把页面完整地址、查询参数作为上报、持久化或普通日志字段；不采集网页正文、Cookie、账号密码、浏览历史或音频下载地址。
- **封面资源地址是上述地址限制的例外**：为了加载图片，可以保留图片完整路径与必要参数。它不能用于扩大网站识别范围，也不应原样写入普通日志。
- 首版控制沿用桌面现有功能；音量、静音、随机／循环、歌单管理暂不纳入。
- 不采集网页歌词正文，不替代现有歌词检索、来源选择或偏移设置；不引入独立遥测、远程采集服务或播放历史库。
- 扩展本地通信不等于整个桌面功能离线：桌面仍按既有设置请求歌词服务，未来加载远程封面也会产生对应图片请求。
- 本节描述确认的目标范围。当前版本实际数据处理以 [PRIVACY.md](../BrowserExtension/PRIVACY.md) 和代码为准；实现新字段时应同步隐私说明。

### 2.2 媒体关联要求

歌名、封面、状态、时间轴和控制应尽量对应同一媒体。不能仅因信息位于同一网页，就将全局 Media Session 元数据与任意 audio/video 拼接。

需要区分网站规则 ID、扩展配置文件 ID、文档 ID、媒体实例 ID 和曲目变化版本。一个媒体实例可连续播放多首歌，文档不变也会切歌；媒体 ID 不能替代曲目版本。曲目版本用于丢弃旧时间轴、旧封面与迟到控制结果，不代表已经获得可持久缓存的稳定歌曲身份。

跨 iframe 信息不能仅靠相同歌名、origin 或“属于同一标签页”强行合并。没有可靠关联证据时应保留不完整信息，并避免使用不可信时间轴或控制其他媒体。

## 4. 通信与状态契约

0.2.1 完整字段与限制见[最新接入说明](浏览器扩展接入.md)。以下基础消息保留，configuration 增加可选 mediaDetailsVersion=1；协商后 session 增加 details，command 增加 trackVersion，result 增加 status／reason／observed。

### 4.1 已实现协议

信封为 `{ "version": 1, "type": "...", "payload": {} }`。Native Messaging 和命名管道传输采用四字节小端长度加 UTF-8 JSON，应用当前限制为单包 256 KiB、JSON 深度 16。stdin/stdout 只能承载协议，诊断不能写入 stdout。

| 方向 | type | 当前 payload |
| --- | --- | --- |
| 扩展 → App | hello | clientId；本机宿主补充 browser |
| App → 扩展 | configuration | revision、enabled、sites；网站项含 id、name、origin、enabled |
| 扩展 → App | ready | revision、origins（已获准的 origin 列表） |
| 扩展 → App | heartbeat | 空对象，每 2 秒 |
| 扩展 → App | session | revision、sequence、documentId、mediaId、url、title、artist、album、isPlaying、positionSeconds、durationSeconds、canSeek |
| 扩展 → App | removed | documentId |
| App → 扩展 | command | requestId、documentId、mediaId、action、可选 seconds |
| 扩展 → App | result | requestId、ok |
| 扩展 → App | suggestSite | origin（用户在扩展弹窗主动添加） |

session 的现有字段名是 **url**，其值实际只传规范化 origin，不是完整网页地址。tabId／frameId 在扩展后台映射；桌面媒体 key 当前由浏览器／clientId、documentId、mediaId 组成。

现有 command.action 为 TogglePlayPause、PreviousTrack、NextTrack、SeekBackward、SeekForward、SeekTo。前后跳转当前使用 5 秒偏移，SeekTo 的 seconds 为目标秒数。

0.2.1 的 details.version=1 包含 trackVersion、source、titleSource、playbackState、可空 positionSeconds／durationSeconds、playbackRate、sampleAgeSeconds、可空 anchorAgeSeconds、seekable、actions、artwork。worker 只在桌面声明详情能力后传输它，旧客户端继续使用基础字段；未知或非法详情被忽略，不关闭健康连接。新增字段必须贯通 rules.js、桌面解析、模型和消费者，不能仅加在页面快照中。WebView 的既有 V1 消息未变。

### 4.2 已实现状态边界

- 配置变化增加 revision，收到匹配 ready 前不接受该修订的媒体。旧 revision、旧 sequence 不替换新快照；注入完成并发送 ready 后才开始接纳页面上报。
- 心跳每 2 秒，连接及媒体有效期为 6 秒；明确断连保留最多 2 秒候选宽限。媒体与心跳分别过期，不能用心跳让旧媒体永久存活。
- 单站未授权／未列入的媒体上报会被忽略，不把它当成传输故障。错误连接关闭后按连接状态和期限回退，不即时绕开网站规则。
- 当前按 Chrome／Edge 类别抑制对应原始 SMTC，会话无法可靠对应到具体浏览器配置文件。这是已知限制，不能宣称支持精确的 SMTC 配置文件去重。
- 0.2.1 详情携带速率与相对传输年龄，桌面按它们外推已知位置，未知位置不外推。不能将不同文档／进程的 performance.now 直接相减。网页不更新的纯 Session 跳转仍是限制。
- 命令按 client 连接、documentId、mediaId 发送；后台使用 tabId + documentId 定向消息。页面关闭或导航后旧目标失败，不改发当前活动页或其他候选。
- MAIN 侧优先调用捕获的 Media Session 处理器；没有处理器时，仅已识别媒体元素可回退到 play／pause／currentTime。上一首／下一首没有可通用调用的元素方法。
- 0.2.1 捕获处理器调用最多等待 750ms，再短时观察效果约 1 秒；relay 超时 2 秒，桌面请求有效期 4 秒。仅 status=observed 且 ok=true 作为确认，旧回执缺少 status 时为 unconfirmed。超时只结束本方等待，无法撤销已经交给网页的异步操作。

## 5. 通用性评估的约束与待决问题

### 5.1 已确认原则

1. 标准 Media Session 与通用媒体观察优先。具体网站适配的必要性由证据决定，不能以 Spotify 的 DOM 选择器或行为作为通用契约。
2. 以能力缺失为正常情况，分别判断元数据、状态、时间轴、封面和每项控制是否可信可用。单项缺失不使整个健康连接转为无限制 SMTC。
3. 元数据与媒体关联优先于“挑选正在播放的第一个元素”。静音、循环或较短时长可以作为线索，但不能单独作为排除规则，正常媒体也可能满足这些特征。
4. 歌曲变化、页面重建、来源切换后，旧代时间轴、封面及命令结果不能污染新会话。采样时间与传输接收时间需要区分；跨进程的单调时钟值不能直接相减。
5. 按帧校验真实来源与权限。继承来源的 about:blank／srcdoc／blob 文档不等于允许采集任意跨域或不透明来源 iframe。

### 5.2 持续评估的实现问题

以下是范围确认时的问题清单。第一阶段已落地的详情协商、曲目版本、来源分离、连续匹配关联、封面与控制确认见第 0 节；剩余复杂场景不能因此视为已解决。

- 如何将 Media Session、DOM／脱离 DOM 的元素和跨文档候选可靠关联；无关联证据时选择哪些有限信息。
- 曲目变化版本如何建立；相同歌名／歌手重复播放和同曲多标签页如何区分。
- 如何表达未知／不可用／过期数据、逐项能力及控制执行结果，并与 0.1.2／V1 协商兼容。
- 网页自己拖动进度后，没有及时调用 setPositionState 时如何检测跳变；不应仅增加轮询频率就宣称解决。
- 如何处理文档启动前已创建的脱离 DOM 音频、提前注册的控制处理器、媒体重建、后台标签节流与休眠恢复。
- 封面从哪一层加载、选择何种尺寸、何时重查、缓存如何绑定会话与曲目版本，以及需要浏览器凭据／blob／data 的图片如何处理。

0.2.1 已选择标准 artwork 候选加桌面异步加载与代次缓存，不增加图片 CDN 扩展权限。当前支持公开 HTTP(S) 默认端口及已授权来源的同源私有地址／端口，不转发 Cookie。blob／data、浏览器认证图片、非标准封面与更强关联方案仍待评估。

## 6. 已有证据与已知缺陷

以下时间均为 Asia/Shanghai，日期为 2026-10-30。实机、模拟、规范能力与推断分开记录，不能互相替代。

| 项目 | 已观察事实 | 能支持的结论／限制 |
| --- | --- | --- |
| Edge Spotify 0.1.2 基本识别 | 15:18:10 桌面日志选中 Browser 的 Enchanted — Taylor Swift；用户随后确认歌曲及歌词推进正常 | 基本链路曾实机通过，不代表所有操作或网站通过 |
| 进度异常触发条件 | 用户后来补充：正常切歌播放进度准确，网页拖动进度后发生偏差，过一段时间又对齐 | 不能继续将其表述为单纯切歌错误；该次拖动的完整数据链尚未采到 |
| 背景视频混用风险 | 后续 Spotify DOM 只读采样：一个播放中的静音循环视频时长 7.882 秒，同期歌曲时长约 146.402 秒 | 页面确实存在非歌曲媒体；不能据此断言它就是用户那次异常的唯一根因 |
| 当前源码隔离模拟 | Media Session 位置设为 90 秒，另一个视频保持 2 秒；扩展仍上报 2 秒／7.882 秒；视频暂停后改报 90 秒／146.402 秒 | 已复现全局元数据与无关媒体时间轴混用缺陷；尚未修复 |
| Media Session 更新依赖 | 当前源码捕获 setPositionState，此后按状态和速率推算 | 网页自身跳转若未及时更新，可能沿用旧锚点；是否发生在用户那次操作仍未确认 |
| 控制定向模拟 | 两标签页隔离模拟只将命令发给指定 tabId／documentId；关闭目标后返回失败，无额外发送 | 路由可行；未完成 Spotify 所有真实控制操作与状态确认 |
| Spotify 封面 | 当前播放区域 DOM 有 64×64 图片；公开图片地址的无登录 HEAD 请求返回 200、image/webp | 图片地址可取得且该次可访问；未直接采样其 Media Session artwork，未下载解码或接入显示 |
| 网易云网页 | 用户表示已在 music.163.com 播放；当时本地监听列表只有 Spotify；诊断工具的站点安全策略阻止页面采样 | 未验证网易云 Media Session、元素、封面、控制或 iframe 结构；不能推断兼容或不兼容 |

早期 Spotify 错误包含：脱离 DOM 的音频无法被找到、继承来源 iframe 的 location.origin 为 null 导致 postMessage 失败。0.1.2 已补充弱引用音频观察、Media Session 路径、有效来源通信和 matchOriginAsFallback；这些修复不包含上述后续发现的背景媒体误选与拖动同步缺口。

上述“尚未修复／接入”条目记录的是 0.1.2 诊断时状态。0.2.1 已通过通用夹具回归背景视频隔离和关联媒体跳转，接入标准封面及控制确认；新版本的真实网站结果仍待补充，不能反向改写旧证据。

忽略目录 `tmp/browser-extension-spotify/` 在原开发环境保留过运行摘要，但不随仓库迁移。新环境应依本文重新复现，不依赖该目录存在。站点采样受工具安全策略限制时，不得绕过限制或把未采样事项写为已通过；该限制也不代表产品扩展必然不能访问该网站。

## 7. 换环境开发与联调

### 7.1 源码与环境

- 携带完整工作区变更或已授权提交后的源码，包含 BrowserExtension、App／Core 桥接、测试、脚本及本文件。0.1.2 ZIP 只含运行文件，不能代替完整开发源码。
- 开始前读取仓库 AGENTS.md 并检查 git status。当前工作区有跨模块未提交变更，不能仅凭 manifest 版本判断本地 EXE 已包含桥接功能，也不能重置其他工作。
- 桌面集成需要 Windows x64、.NET 8 SDK、Windows 11 SDK 10.0.22621。扩展当前为 Chrome／Edge MV3、minimum_chrome_version=120。
- Node.js 负责本地化生成、Vitest 与打包前处理；生产扩展没有 npm 运行依赖。前端依赖以 package-lock.json 为准，新环境使用 npm ci。
- .codegraph 存在时，按 AGENTS.md 先通过 CodeGraph 定位代码；不要在文档维护中顺手升级工具或重建索引。

在仓库根目录按需执行：

```powershell
dotnet restore TaskbarLyrics.sln
dotnet build TaskbarLyrics.sln --no-restore
npm ci
powershell -ExecutionPolicy Bypass -File scripts/package-browser-extension.ps1
```

构建输出被运行中应用占用时，按仓库约定用 scripts/restart-app.ps1 -StopOnly 停止；有真实联调需要时再使用 -NoWait 重启。不要为纯文档变更默认重启应用。

### 7.2 本机安装与更新

1. 启动包含桥接代码的桌面版本，在浏览器播放器设置中点击对应 Chrome／Edge 的配置扩展按钮。
2. 按浏览器确认流程加载解压缩扩展。记录实际加载目录：仓库 BrowserExtension 与 EXE 旁复制的 BrowserExtension 不是同一个目录。修改源码后必须更新实际加载目录，再在扩展页重新加载。
3. 刷新已经打开的媒体页面，使脚本在初始化阶段观察媒体及控制处理器；中途注入无法补获所有早先注册的回调或创建的离屏对象。
4. 将每个测试网站加入监听列表并逐站授权；开启浏览器识别总开关。检查名单、授权和配置确认后再判断采集是否兼容。
5. Native Messaging 注册随用户与 EXE 路径变化，新环境或 EXE 移动后需要重新点击配置按钮；不要复制旧机器注册表值或旧绝对路径。

固定宿主名为 com.taskbarlyrics.browser。宿主清单位于 `%APPDATA%\TaskbarLyrics\BrowserBridge\chrome-host.json` 或 `edge-host.json`，注册于对应浏览器 HKCU NativeMessagingHosts；不需要管理员权限，不开放本机 HTTP 端口。

当前开发 ID 为 `ppefomkojacgcnfhhiapagbobghlipfe`，由 manifest.key 推导；保留公钥以保持开发 ID 稳定，不能把公钥当作商店签名私钥。distribution.json 的 Chrome／Edge 商店 ID 均未配置；不要填写占位 ID、声称已上架或自动安装成功。

扩展版本唯一维护点为 manifest.json；扩展三语文案唯一来源为 TaskbarLyrics.App/text.yaml 的 EXT_ 键。打包脚本会生成 _locales，ZIP 写入忽略目录 tmp/browser-extension。ZIP 内嵌套路径必须使用正斜杠；普通 ZIP 库可能归一化错误路径，回归脚本校验的是原始中央目录与本地头。

### 7.3 诊断证据

- 桌面日志位于实际运行 EXE 旁的 `Logs/app_debug-YYYY-MM-DD.log`，不要默认到 APPDATA 找日志。先确认 EXE 和扩展加载目录，避免诊断旧版本。
- BROWSER 类别记录连接、配置确认和控制结果；0.2.1 在来源／曲目代次／位置已知性变化或显著跳转时记录 MediaTimeline（来源、进度、时长、速率、样本年龄、锚点年龄），不持续记录歌曲标题或图片地址。COVER-UI 可佐证选中的歌曲及封面类型，不能单独证明进度准确。
- 页面低频调试消息记录 Source=element／session／none 及少量布尔状态，不含完整时间样本。未看到调试消息不代表没有采集。
- 复现记录应包含：扩展／桌面版本、浏览器版本、加载目录、已授权 origin、播放设备、步骤与时刻、网页显示位置、桌面位置、媒体来源和能力、命令目标及结果。没有采到的字段标记未知。
- 后续结构化诊断应支持有界、显式启用的采样，避免普通日志持续记录歌曲历史、完整网页地址或带参数的封面地址。

### 8.2 通用行为验收矩阵

- 来源组合：标准 audio／video、脱离 DOM 音频、仅 Media Session、缺失元数据、多个媒体、背景静音循环视频、同曲多标签页、同站多标签页。
- 文档组合：顶层、同源 iframe、继承来源 iframe、明确授权的跨域来源、未授权／不透明来源拒绝、同页不同文档信息无法关联。
- 时间：正常切歌、网页向前／向后拖动、连续拖动、暂停时拖动、桌面跳转、倍速、缓冲、循环、直播／未知时长；分别核对网页与桌面，不能只看歌词是否在动。
- 封面：标准 artwork、多尺寸、稍晚更新、缺失／失败、WebP 等实际格式、快速 A→B→A、来源切换、旧请求忽略取消后返回。
- 控制：逐项能力、送达但不生效、处理器抛错、超时、后台标签页、关闭／导航／媒体重建后旧命令、选中页与前台页不同；不得控制其他候选。
- 配置与恢复：空名单、全部停用、单站撤权、断连降级、重连确认、桌面／浏览器分别重启、休眠恢复、多浏览器与多配置文件。
- 站点样本至少覆盖 Spotify 和网易云网页，并逐步纳入 Bilibili、飞牛音乐等不同类型播放器。每个站点记录实际能力及证据，不预设它提供 Media Session 或与其他站点结构相同。
