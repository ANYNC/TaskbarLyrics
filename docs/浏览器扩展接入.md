# 浏览器扩展接入

已确认的采集范围、当前实现与目标的差距、通用性问题证据及换环境开发步骤见[浏览器扩展开发交接](浏览器扩展开发交接.md)。本文描述当前 0.2.1／V1 接入，媒体详情版本 1 为可选扩展，不改变基础信封。

扩展位于独立目录 `BrowserExtension/`，保持纯 JavaScript；宿主与 SMTC 集成位于 App，网站匹配与优先级策略位于 Core。后续拆仓只需保留协议文档与兼容测试，不需要改变歌词流水线。

## 安装与协议边界

桌面按钮注册 HKCU 的 `com.taskbarlyrics.browser` Native Messaging 宿主，不修改浏览器配置文件。尚未设置商店 ID 时打开本地扩展目录；设置 ID 后打开商店页面。最终安装和网站权限确认由浏览器处理。参考 [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。

同一桌面 EXE 以扩展 origin 参数启动时，在 WPF 与单实例初始化前进入宿主模式。stdin/stdout 专用于四字节小端长度加 UTF-8 JSON 的协议，不写诊断到 stdout。宿主验证允许的扩展 origin，并从 Chrome / Edge 或其 cmd 启动链识别浏览器类别，再转发到当前用户命名管道。不开放网络监听端口。

消息沿用 `{ version: 1, type, payload }`；单包最大 256 KiB、JSON 深度最大 16。未知版本、类型及非法字段安全拒绝；错误连接关闭后按宽限及有效期规则回退原 SMTC 路径。未列入或未获授权的网站媒体被忽略，不视为连接错误。不会从网页声明的 browser 字段决定浏览器身份。

| 方向 | 消息 | 主要载荷 |
| --- | --- | --- |
| 扩展 → App | hello | clientId；宿主补充 browser |
| App → 扩展 | configuration | revision、enabled、sites、可选 mediaDetailsVersion=1 |
| 扩展 → App | ready | revision、获准 origin 列表 |
| 扩展 → App | heartbeat | 空对象，每 2 秒 |
| 扩展 → App | session | revision、递增 sequence、documentId、mediaId、url（值为规范化 origin）、媒体元数据及播放时间、可选 details |
| 扩展 → App | removed | documentId |
| App → 扩展 | command | requestId、documentId、mediaId、action、可选 seconds 与 trackVersion |
| 扩展 → App | result | requestId、ok、可选 status／reason／observed |
| 扩展 → App | suggestSite | 用户从弹窗主动添加的 origin |

配置修订变化后必须收到匹配的 ready 才接纳该修订的候选；过期 ready / session 忽略。会话超过 6 秒未更新即失效；健康连接无媒体时不恢复通用 SMTC。命令只发送到当前文档与媒体元素，失败不控制其他标签页。WebView 的网站增删、开关、排序消息也使用 V1 信封，宿主验证完整排序排列。

0.2.1 的 result.status 区分 observed／unconfirmed／rejected；只有观察到效果且 ok=true 才作为确认，旧回执缺少 status 时记为尚未确认。页面短时观察约 1 秒，relay 超时 2 秒，桌面请求有效期 4 秒；文档／曲目不匹配、未知请求和迟到回执不确认原命令。上一首／下一首允许目标曲目版本变化，其余动作要求版本保持。具体网站是否正确响应仍需实机验收。

details.version=1 包含 trackVersion、source（element／media-session／associated-element）、titleSource、playbackState、可空 positionSeconds／durationSeconds、playbackRate、sampleAgeSeconds、可空 anchorAgeSeconds、seekable 区间、actions 和 artwork 候选。新增客户端只在 configuration 声明 mediaDetailsVersion=1 后向桌面发送 details；旧客户端基础字段继续可读，未知或非法详情被忽略且不使健康连接降级。数值严格校验，样本传输年龄不得超过 6 秒。采样年龄通过同文档单调时钟及本机消息传输年龄累计，不直接比较不同进程的 performance.now；桌面继续按接收后的时间和速率外推。

标准封面由桌面端异步加载并复用代次缓存。普通跨域候选限公开 HTTP(S) 默认端口，同源候选可使用用户已授权站点的私有地址／端口；每次重定向重新校验，DNS 解析与目标地址校验在连接边界一起完成。不转发浏览器 Cookie，不申请额外图片 CDN 扩展权限。当前最多 8 个候选、8 个可跳转区间、单图片 1 MiB、最多 3 次重定向，读取沿用缓存的取消与 5 秒超时。无标准 artwork 或需登录的图片继续占位。

## 无 DOM 媒体与继承来源页面

扩展 0.1.2 同时观察 DOM 媒体和播放后仍未挂入 DOM 的音频对象，以弱引用保留观察关系。没有可用媒体元素时，可使用 Media Session 的元数据与声明播放状态，捕获后续 setPositionState 时间轴；未知时间轴不推断进度或开放拖动，原生调用返回值及失败语义保留。参考 [Media Session 标准](https://www.w3.org/TR/mediasession/)。

部分播放器使用继承网站来源的内嵌页面，其 location.origin 为 null，但浏览器真实来源为网站 origin。注入使用 matchOriginAsFallback，页面通信使用有效来源；后台仅信任浏览器提供的 MessageSender.origin，校验授权和精确网站规则，不使用网页载荷或顶层标签地址推断来源；不透明来源被拒绝。参考 [Chrome 脚本注册](https://developer.chrome.com/docs/extensions/reference/api/scripting#type-RegisteredContentScript) 与 [MessageSender](https://developer.chrome.com/docs/extensions/reference/api/runtime#type-MessageSender)。

## 发布前相关验收

- 旧 settings.json 缺字段时继续通用监听，浏览器默认关闭；配置网站不隐式开启浏览器卡片。
- 两个网站同时播放按顺序选择；较高顺序暂停后转向正在播放的网站；同站同状态保持当前页。
- 网易云暂停、浏览器播放时按播放状态切换；双方播放时按外层播放器顺序。
- 空列表、全部关闭、未授权、无标准媒体元素时无扩展候选，健康连接不改用任意网站的 SMTC。
- 断开扩展超过宽限/心跳期限后恢复通用监听，恢复连接同步配置后再次限制网站。
- 撤销单站权限不视作全局断线；多个 Chrome / Edge 与配置文件组合需要实机验证。
- 页面导航、标签关闭后旧控制不作用于新页面；检查暂停、播放、进度拖动及上一首/下一首能力。
- 浏览器和桌面分别重启、休眠恢复、网页播放器重建、飞牛音乐与 Bilibili 实际页面验证。
- 本地开发安装和各商店正式包分别确认 Native Messaging origin 与实际扩展 ID 一致。
