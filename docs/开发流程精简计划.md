# 开发流程精简计划

## 目标与边界

减少与任务风险无关的必读、必跑和固定代理流程，让验证范围由实际影响决定。保留用户数据、设置迁移、WebView 协议、缓存身份、线程与资源生命周期、DPI 单位等兼容性边界。

## 第一阶段：精简规则（本次）

1. 将 `AGENTS.md` 收敛为项目边界、按影响范围验证、工作区保护和交付授权；删除固定模型分工、无条件完整验证与自动重启。
2. 将 Clean Code Guardian 和 WebView UI Auditor 改为按需使用的审查工具，避免每次完整读取参考资料；允许用户明确要求“审计并修复”时继续修复。
3. 统一 WebView 规范、项目契约和变更记录中的验证与重启表述，避免同一事项出现相互冲突的要求。
4. 以规则交叉检查和 `git diff --check` 验收；本阶段不改变应用代码、测试逻辑或用户数据。

## 第二阶段：改善设置契约测试（实现完成，App 验证待环境恢复）

1. 保留设置页字段与导航的 DOM 契约；由 Vitest 验证页面行为、由 App 测试验证消息解析和设置持久化。
2. 删除对具体函数名、C# `case` 文本、CSS 选择器、文案和控件实现的源码字符串断言。
3. 将生产 Web 资源目录的测试文件边界检查独立为 `production-web-assets.tests.ps1`，并接入验证脚本。
4. Web 验证与生产资源边界检查已通过。Settings/App 测试、完整验证和零警告构建因 NuGet.org SSL 凭证错误（NU1301）未完成；包还原恢复后补跑这些检查。

`SettingsWindow` 的真实宿主消息副作用目前没有独立的自动化集成测试。旧检查只搜索 C# `case` 文本，不能验证副作用；涉及宿主分派的行为变化仍需相应 Windows 手工验证，后续若提取可测试边界再补自动化覆盖。

## 第三阶段：用实际任务校准（后续）

在几次不同范围的真实改动中，检查是否能明确解释所选验证层级、是否出现遗漏的兼容性检查，以及规则是否仍造成重复阅读或无效执行。只根据具体遗漏和成本调整规则，不恢复普遍性强制流程。

## 仓库外规则

当前会话提供的“先用 CodeGraph 再搜索”说明不在仓库 `AGENTS.md` 中，修改仓库文件无法取消该注入规则。建议在其来源改为：跨文件调用链和动态派发追踪优先用 CodeGraph，简单文件或文本定位可直接用 `rg`。
